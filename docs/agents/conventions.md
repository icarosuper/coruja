# Conventions

How code is laid out. Rules that apply everywhere (readability, commits) are in `CLAUDE.md` and
are not repeated here.

## Layout

```
src/
  worker/        Hono app (API, later the MCP endpoint) and cron.ts (the daily cron). Entry: index.ts
    bindings.ts  Worker bindings as a module type (see below); app-env.ts adds the request variables
    auth.ts      token and team password middlewares; errors.ts ApiError; validation.ts zod schemas
    routes/      one sub-app per resource (devs, me, months): HTTP only, no queries
    store/       reads and writes in D1 per area (devs, profile, months, sheet, balances)
    testing/     test-only helpers: useTestDatabase (Miniflare D1), typed test client
    db/          Drizzle: schema.ts (tables), client.ts (createDatabase)
  web/           Svelte 5 SPA. Entry: main.ts → App.svelte (header, nav, routes). api.ts: typed client
                 + `call()` (throws `ApiFailure` with the Portuguese message from errors.ts);
                 router.svelte.ts, session.svelte.ts, calendar.ts (today in São Paulo), format.ts,
                 xlsx.ts. Screens: month/, profile/, admin/, TokenEntry. lib/: shadcn-svelte.
  schedule/      Domain rules as pure functions — no D1, no Hono, no Date.now() inside.
                 dates.ts (YYYY-MM-DD helpers, UTC), holidays.ts, shifts.ts (day kinds, hours by
                 calendar month, segment validation), preferences.ts (profile rules → preference
                 per date), scheduler.ts (suggestRoster), balance.ts (a month's hours vs share).
  sheet/         The manager's Excel sheet: csv.ts (CSV reader), roster.ts (Banking roster out of
                 the exported sheet), export.ts (Office Script and paste grid back into it),
                 testing/ (builds sheets in tests). Pure too.
scripts/         Dev tools run with bun (not deployed): suggest-roster.ts + example-team.json
migrations/      SQL generated by drizzle-kit (+ meta/ journal), applied by wrangler — not hand-edited (one exception, below)
docs/agents/     docs for agents (this folder)
docs/guides/     how-tos for humans
```

The domain owns its vocabulary: `DAY_KINDS` (`shifts.ts`), `PREFERENCES` and
`PREFERENCE_RULE_KINDS` (`preferences.ts`) live in `src/schedule/` and the schema imports them, not the other way around. `src/schedule/` never imports from `src/worker/` or
`src/sheet/`; `src/sheet/` may import `src/schedule/`.

There is no `src/shared/` for API payloads on purpose: the web app gets them from `AppType`.

## API and the typed client

- Every route lives under `/api` (`basePath` in `src/worker/index.ts`).
- Routes are **chained** (`app.get(...).post(...)`) or grouped in sub-apps mounted with
  `.route('/path', subApp)`. A route registered as a separate statement (`app.get(...)` on its
  own line) still works at runtime but disappears from `AppType`.
- Return with `context.json(...)` so the response type is inferred. Validate input with a validator
  middleware so the input type reaches the client too.
- The web app calls `api.api.<path>.$get()` / `$post({ json })` from `src/web/api.ts`. It never
  declares its own request/response types and never calls `fetch` on `/api` directly.
- A route validates with `validate(target, schema)` (`src/worker/validation.ts`), calls one `store/`
  function and returns `context.json(...)`. Failures are thrown as `ApiError(status, code, details)`
  and answered as `{ error: code, ...details }`; the code is English, the web app shows Portuguese.
- Admin routes use `requireTeamPassword`, the rest `requireDev` (`context.var.dev` is the caller).
- Tests call the app with the typed `clientFor(env)` (`src/worker/testing/client.ts`) on a real
  local D1: `useTestDatabase()` at the top of the file starts Miniflare once, applies `migrations/`
  and empties every table before each test. No server needed.

## Database

- Tables live in `src/worker/db/schema.ts`. After changing it: `bun run db:generate`, then
  `bun run db:migrate:local`.
- Route handlers get a Drizzle instance with `createDatabase(context.env.DB)` and pass it to `store/`.
- An operation that writes more than one statement goes through one `runBatch` (atomic; D1 has no
  interactive transactions). Many rows: `insertRows`, which keeps each statement under D1's 100
  bound parameters.
- Enum-like columns are `text` with the allowed values exported as `as const` arrays from the
  schema (`PREFERENCES`, `DAY_KINDS`...) **and** a `CHECK` in SQL: reuse the arrays in validators
  and UI instead of retyping the values.
- Dates are `YYYY-MM-DD` text, months `YYYY-MM` text, timestamps `integer` milliseconds
  (`mode: 'timestamp_ms'`). Derived values (hours, balances, readiness) are never stored.
- Migrations must stay backward compatible with the code currently deployed (decisions #17).
- The one hand edit allowed in generated SQL: when drizzle-kit rebuilds a table (dropping a column
  used by a `CHECK` or a foreign key), it wraps it in `PRAGMA foreign_keys=OFF/ON`, which D1
  ignores — the `DROP TABLE` then fails on the tables that reference it. Replace them with
  `PRAGMA defer_foreign_keys = on;` / `PRAGMA defer_foreign_keys = off;`. Try the migration on a
  local D1 that has rows before committing it.

## TypeScript

- Three projects: `tsconfig.web.json` (DOM, checked by `svelte-check`), `tsconfig.worker.json`
  (Workers runtime types from `worker-configuration.d.ts`, checked by `tsc`) and
  `tsconfig.scripts.json` (Bun types, for `scripts/`).
- The web project also type-checks every Worker file reachable from `AppType`. Those files must not
  use Workers **globals** in their types: bindings are typed in `src/worker/bindings.ts` with module
  imports from `@cloudflare/workers-types`, not with the global `Env`. Keep it in sync with
  `wrangler.jsonc`.
- TypeScript stays on 6.x: `svelte-check` does not support 7 without experimental flags.
- `noUncheckedIndexedAccess` is on.

## Svelte

- Svelte 5 with runes, `<script lang="ts">`. Biome formats and lints `.svelte` files
  (`html.experimentalFullSupportEnabled`).
- UI strings in Portuguese; everything else in English.
- Routes are hashes (`router.svelte.ts`, decisions #27); links come from `links`.
- Every API call goes through `call(api.api....)`: it returns the body or throws `ApiFailure`, whose
  `message` is ready to show (a toast with `svelte-sonner`). A new error code gets its Portuguese
  text in `errors.ts`.
- Response types come from the API with `InferResponseType` (`month/types.ts`), never by hand.
- The web app may import pure functions from `src/schedule/` (dates, shift hours); never from
  `src/worker/` beyond `import type`.
- Colours: palette classes (`bg-stone-100`, `text-sky-700`…) without `dark:` variants; the dark
  theme redefines the palette (decisions #27). A dev's colour comes from `colorOf(devId)`.
- shadcn components live in `src/web/lib/components/ui/` and are ours to edit; add more with
  `bunx shadcn-svelte@latest add <name>`.
