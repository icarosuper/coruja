# Conventions

How code is laid out. Rules that apply everywhere (readability, commits) are in `CLAUDE.md` and
are not repeated here.

## Layout

```
src/
  worker/        Hono app (API, later the cron handler and the MCP endpoint). Entry: index.ts
    bindings.ts  Worker bindings as a module type (see below)
    db/          Drizzle: schema.ts (tables), client.ts (createDatabase)
  web/           Svelte 5 SPA. Entry: main.ts → App.svelte; api.ts is the typed API client
  schedule/      Domain rules as pure functions — no D1, no Hono, no Date.now() inside.
                 dates.ts (YYYY-MM-DD helpers, UTC), holidays.ts, shifts.ts (day kinds, hours by
                 calendar month, segment validation), preferences.ts (profile rules → preference
                 per date), scheduler.ts (suggestRoster).
  sheet/         The manager's Excel sheet: csv.ts (CSV reader), roster.ts (Banking roster out of
                 the exported sheet). Pure too; the Office Script generator goes here later.
scripts/         Dev tools run with bun (not deployed): suggest-roster.ts + example-team.json
migrations/      SQL generated by drizzle-kit (+ meta/ journal), applied by wrangler — never hand-edited
docs/agents/     docs for agents (this folder)
docs/guides/     how-tos for humans
```

The domain owns its vocabulary: `DAY_KINDS` (`shifts.ts`), `PREFERENCES` and
`PREFERENCE_RULE_KINDS` (`preferences.ts`) live in `src/schedule/` and the schema imports them, not the other way around. `src/schedule/` never imports from `src/worker/` or
`src/sheet/`; `src/sheet/` may import `src/schedule/`.

There is no `src/shared/` for API payloads on purpose: the web app gets them from `AppType`.

## API and the typed client

- Every route lives under `/api` (`basePath` in `src/worker/index.ts`).
- Routes are **chained** (`app.get(...).post(...)`) or grouped in sub-apps mounted with
  `.route('/path', subApp)`. A route registered as a separate statement (`app.get(...)` on its
  own line) still works at runtime but disappears from `AppType`.
- Return with `context.json(...)` so the response type is inferred. Validate input with a validator
  middleware so the input type reaches the client too.
- The web app calls `api.api.<path>.$get()` / `$post({ json })` from `src/web/api.ts`. It never
  declares its own request/response types and never calls `fetch` on `/api` directly.
- Tests call the Hono app directly with `app.request(...)` — no server needed.

## Database

- Tables live in `src/worker/db/schema.ts`. After changing it: `bun run db:generate`, then
  `bun run db:migrate:local`.
- Route handlers get a Drizzle instance with `createDatabase(context.env.DB)`.
- Enum-like columns are `text` with the allowed values exported as `as const` arrays from the
  schema (`PREFERENCES`, `DAY_KINDS`...) **and** a `CHECK` in SQL: reuse the arrays in validators
  and UI instead of retyping the values.
- Dates are `YYYY-MM-DD` text, months `YYYY-MM` text, timestamps `integer` milliseconds
  (`mode: 'timestamp_ms'`). Derived values (hours, balances, readiness) are never stored.
- Migrations must stay backward compatible with the code currently deployed (decisions #17).

## TypeScript

- Three projects: `tsconfig.web.json` (DOM, checked by `svelte-check`), `tsconfig.worker.json`
  (Workers runtime types from `worker-configuration.d.ts`, checked by `tsc`) and
  `tsconfig.scripts.json` (Bun types, for `scripts/`).
- The web project also type-checks every Worker file reachable from `AppType`. Those files must not
  use Workers **globals** in their types: bindings are typed in `src/worker/bindings.ts` with module
  imports from `@cloudflare/workers-types`, not with the global `Env`. Keep it in sync with
  `wrangler.jsonc`.
- TypeScript stays on 6.x: `svelte-check` does not support 7 without experimental flags.
- `noUncheckedIndexedAccess` is on.

## Svelte

- Svelte 5 with runes, `<script lang="ts">`. Biome formats and lints `.svelte` files
  (`html.experimentalFullSupportEnabled`).
- UI strings in Portuguese; everything else in English.
- Router and component library: not chosen yet, decided together with the screens.
